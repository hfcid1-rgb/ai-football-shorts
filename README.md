# AI Cinematic Football Shorts Generator

Generates a short, clearly-labeled **fictional** cinematic football highlight video
(vertical 9:16, ~25–30s) from a single reference character image, using the
**Runway API** (image-to-video) + **FFmpeg** post-production, orchestrated by a
manually-triggered **GitHub Actions** workflow.

Story: a stylized cartoon Al Ahly SC character scores a dramatic goal in a fictional
match against ENPPI SC. This is **AI-generated fan content**, not real match footage,
and is labeled as such in the final video.

---

## 1. What this project does

- Takes a reference image of a character (`assets/reference/character.png`)
- Sends it to Runway's image-to-video model, once per scene, using prompts stored in
  `prompts/scenes.json`
- Downloads the generated clips
- Stitches them together with FFmpeg: consistent resolution/frame rate, vertical
  1080x1920 crop, cinematic cuts, optional slow-motion around the goal, fades,
  loudness normalization, and safe text overlays (titles are burned in with FFmpeg,
  **not** generated by the AI model, so Arabic/English text stays crisp)
- Uploads the final MP4 as a **GitHub Actions artifact** (it is intentionally
  **not** committed back into the repo)

## 2. Where to upload the reference image

Upload your character image to:

```
assets/reference/character.png
```

The workflow checks for this file before calling Runway. If it's missing, the run
fails immediately with a clear message — no credits are spent.

## 3. How to run the GitHub Action

1. Go to the repo's **Actions** tab.
2. Select **"Generate Cinematic Football Short"**.
3. Click **"Run workflow"**.
4. Choose a `mode` input (`test` or `full` — see below). Default is `test`.
5. Click **Run workflow** and wait for it to finish.
6. Open the completed run and download the **`football-short`** artifact from the
   run summary page.

You need `RUNWAYML_API_SECRET` already set as a repository secret
(**Settings → Secrets and variables → Actions**). This project never prints, logs,
or commits that value.

## 4. TEST mode vs FULL mode

| | TEST (default) | FULL |
|---|---|---|
| Clips generated | 1 short test clip | All 13 scenes |
| Purpose | Validate Runway connectivity + character consistency cheaply | Produce the complete ~25–30s short |
| Trigger | Default `workflow_dispatch` input | Must be **explicitly** selected as `mode: full` — never runs automatically |
| Approx. credit use | Low (one clip) | Significantly higher (13 clips) |

**Always run TEST mode first.** Confirm the single test clip looks right (character
identity, kit, proportions) before ever selecting FULL mode.

## 5. Where to download the finished artifact

After a workflow run completes, open it in the **Actions** tab → the run's summary
page has an **Artifacts** section at the bottom → download `football-short` (a zip
containing the final `.mp4`, plus the raw test clip in TEST mode).

## 6. Credit-usage warning

Runway billing is credit-based and generation is not free. `full` mode generates up
to 13 image-to-video clips — this can consume a large portion of a limited credit
balance in one run. This project:

- Defaults to `test` mode everywhere
- Requires an explicit, manual `mode: full` selection to spend more
- Never runs on push/PR/schedule — only on manual `workflow_dispatch`
- Never loops or retries expensive calls automatically beyond one bounded retry

Check your remaining Runway credits before running `full` mode.

## 7. Security warning about API keys

- The Runway key lives **only** in the `RUNWAYML_API_SECRET` GitHub Actions secret.
- It is injected as an environment variable at run time and is never written to a
  file, echoed to logs, or committed.
- Do not paste the key into issues, PRs, commit messages, or this README.
- If the key is ever exposed, rotate it immediately in the Runway dashboard and
  update the GitHub secret.
- This project does not delete or modify the secret — only reads it at runtime.

## Project structure

```
.github/workflows/generate-video.yml   Manually-triggered workflow (test/full)
assets/reference/character.png         Your uploaded reference image (not committed by CI)
assets/audio/                          Optional user-provided audio (music/SFX), no copyrighted broadcast audio
config/settings.json                   Model, resolution, ratio, timing config
prompts/scenes.json                    The 13-scene structured prompt list + negative prompts
scripts/check-reference.js             Fails fast if character.png is missing
scripts/generate.js                    Calls Runway image-to-video (test or full mode)
scripts/postprocess.js                 FFmpeg pipeline: crop/scale, cuts, slow-mo, fades, overlays, loudness, encode
output/                                Local output dir (gitignored; CI uploads it as an artifact instead)
package.json
.gitignore
```

## Notes on content & authenticity

- The output is a **fictional, AI-generated** scene. Overlays include
  "AI FOOTBALL CINEMATIC" so it is never mistaken for real broadcast footage.
- No real match footage, broadcast commentary, or copyrighted music is used or
  committed. Audio is optional and user-supplied.
- The video model is never asked to render important text (club names, "GOAL",
  etc.) — all text is added safely in FFmpeg post-production to avoid garbled
  AI-generated typography.

## Current Runway API settings (reviewed Aug 2026)

This project uses `gen4_turbo`, portrait `720:1280`, and 2-second clips. The TEST run therefore requests one 2-second generation; FULL requests 13 × 2-second generations (~26 seconds before post-processing). At the current Gen-4 Turbo rate of 5 credits/second, that is approximately 10 credits for TEST and 130 credits for FULL, subject to Runway pricing changes.
